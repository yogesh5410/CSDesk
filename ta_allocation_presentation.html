The Challenge

Why Manual Allocation Breaks Down

Every semester, ~100 M.Tech & PhD scholars must be allocated across 20+ departmental courses. Handcrafted spreadsheets and naive greedy assignment algorithms always fail due to compounding constraints.

🗓️

Timetable Slot Clashes

Lectures, tutorials, and multi-slot labs occupy intricate timetable blocks (e.g. A12, OWQSU, P23&T23). M.Tech students have their own coursework that cannot overlap with their teaching assistant duties.

⚔️

Contested Preferred TAs

Multiple faculty members frequently request the same standout scholars. Resolving who gets whom requires evaluating thesis supervisor priorities and cascading availability across all courses simultaneously.

⚖️

Severe Demand Shortages

When faculty demand (e.g. 100 TAs) exceeds available scholars (e.g. 90 TAs), naive allocation starves smaller courses. Demand must be fulfilled proportionally across all clashing slots.

Rules & Criteria

Mathematical Problem Formulation

The solver operates under strict Hard Constraints (guaranteed feasibility) and Soft Optimization Objectives (maximizing satisfaction).

Hard Constraints (Must Satisfy)
✕

Zero Timetable Clashes: If TA $t$ is enrolled in course $R$, then $t$ cannot TA for course $C$ if $\text{Slots}(R) \cap \text{Slots}(C) \ne \emptyset$.

✕

Strict Workload Limit: Each TA is assigned to at most 1 course ($\sum_c x_{c,t} \le 1$).

✕

Demand Ceiling: Total TAs allocated to course $C$ cannot exceed requested demand ($\sum_t x_{c,t} \le \text{Demand}_c$).

Soft Objectives (Maximized by Solver)
✓

Faculty Preference Ranks: Higher rank preferences receive massive objective weights ($W_1 > W_2 > W_3$).

✓

Thesis Supervisor Priority: When multiple faculty contest a TA, the student's thesis advisor receives priority boost.

✓

Proportional Satisfaction: Diminishing marginal returns ensure every course receives fair percentage fulfillment.

The Algorithm

Why Google OR-Tools CP-SAT?

Constraint Programming (CP) over Boolean Satisfiability (SAT) searches the global decision space rather than taking greedy heuristic shortcuts.

1. Exact Global Optimum

With 21 courses and 95 TAs, there are ~2,000 binary decision variables ($x_{c,t}$). CP-SAT evaluates the holistic combination rather than ordering-dependent greedy choices.

x_{c,t} \in \{0, 1\} \quad \forall c \in C, t \in T

2. Rules as Objective Weights

Instead of brittle nested `if/else` conditions that fight each other, complex department policies are encoded as mathematically composed integer weights in the objective function.

\max \sum_{c,t} \text{Reward}(c, t) \cdot x_{c,t}

3. Ultra-Fast Execution

Powered by modern SAT solver techniques (lazy clause generation, conflict-driven clause learning). Finds verified optimal allocations in under 0.5 seconds.

\text{Solve Time} < 500\text{ms}
System Design

Full-Stack System Architecture

Seamless orchestration across browser UI, REST API, vector-level PDF document parsers, and the optimization engine.

Client Layer (React 19 SPA)

  • Role-Based View: tailored portals for Admin, Faculty, TA, Student.
  • Interactive Faculty Requirements: Searchable dropdown with ranking.
  • Sticky Viewport Sidebar & Header with instant role impersonation.
  • Real-time Solver execution logs and progress streaming.

Server Layer (Node.js & Python)

  • Node.js 20 Express API handling authentication, uploads, and DB syncing.
  • Python Poppler PDF extraction (`pdftotext -bbox-layout`) for grid layout.
  • OR-Tools CP-SAT bridge spawned asynchronously with streaming stdout.
  • PostgreSQL with Row Level Security (RLS) for protected records.
Pipeline: PDF/CSV Uploads ➔ Automated Grid Normalization ➔ CP-SAT Solver ➔ Official Publication Zero Data Leakage

Faculty Portal

Dynamic Requirements Collection

Replacing static Excel spreadsheets with an interactive web portal where instructors submit demand directly.

Searchable TA Dropdown

Faculty search any TA across CSE and DSAI by Roll Number (e.g. M25...), Name, or Email. No typing errors or misspelled roll numbers.

Priority Ranking Controls

Selected TAs are arranged with intuitive ▲/▼ rank order buttons. Rank #1 gives the highest bonus weight to the solver, ensuring top choices are prioritized.

Co-Instructor Sync

For team-taught courses (e.g. CSL100 with Dr. Vishwesh, Dr. Gagan, Dr. Shivam), any instructor can submit or view the latest saved requirements in real-time.

Admin Control: Administrators can open/close collection with one click, track submitted vs. pending courses in real-time, or upload fallback CSVs. Pending courses are gracefully treated as having 0 demand when the solver runs.

End-to-End Administrator Workflow

From raw schedule documents to a published campus-wide allocation in 5 easy steps.

Upload Sources

Admin uploads Timetable PDF, Course Catalog PDF, and Student CSVs. Parsers extract grids automatically.

STEP 2

Collect Demands

Admin opens collection. Faculty log in and submit TA counts and preference rankings from their portal.

STEP 3

Run Solver

Admin triggers CP-SAT. Real-time progress bar streams solving iterations to global optimality.

STEP 4

Publish Results

Admin inspects analytics and clicks "Publish Results". Faculty, TAs, and students immediately see their view.
