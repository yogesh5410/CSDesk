Problem Statement & Motivation

Why Did We Build This System?

Overcoming the massive inefficiencies of manual lab computer maintenance.

❌ The Legacy Manual Process
  • • Physical Footwork: Lab assistants must physically walk to 80+ workstations in TL1, TL2, ED1, ED2 with USB drives or type commands on each keyboard.
  • • Hours Wasted: Rolling out a single package (e.g., Python AI Stack or GCC update) takes 3–4 hours across all machines.
  • • Zero Visibility: No centralized way to know which machines are on/off, which package updates failed, or which student PC has disk space issues.
  • • SSH / Ansible Vulnerabilities: SSH requires keeping port 22 open on all student machines and managing 80+ private keys.
✅ The CSDesk Automated Solution
  • • 1-Click Parallel Execution: Dispatch any shell command or script across 40+ computers simultaneously in under 1 second.
  • • Live Line-by-Line Streaming: Watch terminal outputs (stdout/stderr) scroll live in the web browser console using WebSockets.
  • • Room-First Fleet Filtering: Discrete room isolation (TL1, TL2, ED1, ED2); commands only target computers physically in that lab.
  • • Zero Inbound Open Ports: Agent uses outbound WebSockets over port 443; zero open listening ports on student computers!

Execution Flow #1

What Happens When a Lab PC Boots Up?

Zero human intervention: Automatic discovery and heartbeat lifecycle.

1

PC Power On

Student turns on PC in TL1. Ubuntu boots up. Linux systemd starts csdesk-agent.service.

systemctl enable --now
2

Encrypted WSS Handshake

Daemon establishes outbound WSS connection to Render server on port 443 with pre-shared token.

wss://.../ws/lab-agent
3

Token Validation

Render validates LAB_AGENT_TOKEN. Registers PC in memory under room TL1.

REGISTER_ACK: OK
4

Dashboard Goes Live

Server broadcasts AGENT_CONNECTED to Vercel. PC card pops up with green dot!

PC-22 Online in TL1
⚡ Self-Healing Loop: If university Wi-Fi temporarily drops or Render sleeps, the agent daemon auto-reconnects every 5 seconds. Zero reboot required!

Security Architecture

The 4-Layer Defense Shield

Why this system is 100% safe from student tampering and rogue Wi-Fi attacks.

L1

Google OAuth + Institute Whitelist

Only verified @iitbhilai.ac.in accounts can log in. External or unauthenticated visitors are rejected at the login gateway.

L2

Server-Side RBAC Enforcement

POST /api/lab-automation/execute checks req.user.role === 'admin'. Students receive HTTP 403 Forbidden even if they use curl/Postman on college Wi-Fi.

L3

Outbound-Only WebSockets + Secret Token

Lab PCs have zero open inbound ports (unlike SSH). Agent initiates outbound connection using LAB_AGENT_TOKEN. LAN port scans see nothing!

L4

Daemon Destructive Command Blocker

Hardcoded blacklist blocks rm -rf /, mkfs, fork bombs :(){ :|:& };:, and disk partition wipes. Fails safe with Exit Code 126.

Engineering Highlights

Key Technical Innovations

Design decisions that set CSDesk apart from legacy tools.

1. Zero External Pip Dependencies

Legacy tools (Ansible/Salt) require virtual environments, compilers, and pip packages. CSDesk uses 100% Python 3 standard library. Installs in 2 seconds on fresh Ubuntu without broken pip issues.

2. Dual-Redundancy Streaming Architecture

Primary stream over WebSockets gives real-time sub-50ms log streaming. Automatic REST polling fallback runs every 1000ms, ensuring zero log loss even on spotty Wi-Fi networks.

3. Dynamic Inline PC Labeling

Administrators can rename technical hostnames (t1-pc-cl1) to clean desk labels (PC-01) with an inline Pencil icon. Synced to both browser localStorage and server memory.

4. Cross-Platform Engine (Ubuntu + Windows)

While university labs run Ubuntu systemd, the Python daemon detects host OS and executes commands via bash on Linux or PowerShell on Windows machines.
